# Créer une User Story

## Quand l'utiliser

Quand un besoin doit devenir une unité de travail.

## Prompt prêt à copier

```text
Transforme ce besoin en User Story focalisée.

Inclure :
- titre précis ;
- valeur utilisateur ou objectif technique ;
- scope ;
- hors scope ;
- critères d'acceptation objectivement vérifiables ;
- edge cases importants ;
- dépendances ;
- impact sécurité ;
- impact data ;
- impact UI/API ;
- méthode de vérification.

N'ajoute aucun coût financier.
N'ajoute pas de détail d'implémentation sauf contrainte déjà validée.
Si le besoin est trop gros, dis-le et propose un découpage.
```

## Sortie attendue

Une Story testable et prête à clarifier.
